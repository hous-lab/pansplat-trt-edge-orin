# PanSplat TRT edge - deployment artifacts

Prebuilt artifacts for [pansplat-trt-edge-orin](https://github.com/hous-lab/pansplat-trt-edge-orin), the TensorRT deployment of PanSplat (CVPR 2025) on Jetson AGX Orin. The GitHub repo holds the pipeline; this repo holds the large regenerable artifacts so a consumer can skip ONNX tracing and go straight to engine builds and gates.

## Files

| Path | Contents | Size |
|---|---|---|
| `onnx/` | 23 graphs: the 21 deployment graphs + 2 split intermediates (manifest: `scripts/release_manifest.yaml` in the GitHub repo) | ~0.65 GB |
| `engines/x86-trt10.16/` | 21 engines, built with trtexec (TensorRT 10.16) on x86 (A6000, sm_86) | ~0.3 GB |
| `engines/orin-trt10.3/` | 21 engines, built with trtexec (TensorRT 10.3) on Jetson AGX Orin (sm_87) | ~0.3 GB |
| `golden_512.npz` | golden-tier runner inputs (single MP3D scene, 512x1024), self-produced quality anchor | 331 MB |

## Usage

Clone the GitHub repo, then:

```bash
export PANSPLAT_SKIP_EXPORT=1          # use HF onnx/ instead of tracing
mkdir -p export/onnx export/engines
# copy onnx/*.onnx into export/onnx/, engines/<platform>/ into export/engines/
bash run_pipeline.sh                   # gates run against the prebuilt artifacts
```

`PANSPLAT_INPUTS=golden` plus the anchor npz (placed at `export/golden_512.npz`) runs the golden tier: per-field cosine >= 0.99978 and render PSNR against the torch anchors in the npz - the accuracy gate, dataset-free (the npz carries the anchor scene's context tensors; xy grids come from the checkpoint). The default smoke tier runs structural gates only (verify_smoke.py): the 21-engine chain bakes the golden-scene encoding into the gh_s*_cnn engines (graph constants) and the xy grids into the mlp engines - a single-scene feature-cache deployment (see docs/01_architecture.md in the GitHub repo). ## Platform pairing

Engines are not portable across TensorRT major versions or GPU architectures. Use `engines/orin-trt10.3/` on Jetson AGX Orin (JetPack 6.2, TensorRT 10.3), and `engines/x86-trt10.16/` on x86 hosts with TensorRT 10.16. Any other pairing: rebuild from `onnx/` with trtexec (`run_pipeline.sh` step 4 does this; the gh_s3 pair needs a large Myelin workspace, see `PANSPLAT_POOL_MB` in `docs/02_pipeline.md`).

## Scene locking (read this)

- The gh_s*_cnn engines carry the golden scene's encoded features as graph constants and the gh_s*_mlp engines bake the checkpoint's xy sampling grids. The 21-engine chain is a single-scene feature-cache deployment: only disp_candi and the residual chain vary at runtime. Golden-scene inputs + the anchor npz give the contract numbers; other inputs are smoke-tier only.

## Provenance

- ONNX graphs: traced with the export chain in the GitHub repo from the upstream PanSplat checkpoint (`nvpl49ge`, 512x1024 mp3d tier). The checkpoint itself is upstream-hosted (link-only, see `ckpts/README.md` in the GitHub repo) and is NOT rehosted here, nor are any derivative weights.
- `golden_512.npz` is self-produced (pipeline-extracted runner inputs on the anchor scene); it contains MP3D image pixels from the single anchor scene, kept here as the quality anchor. It is not used for training.
- Engine serialization: trtexec CLI only. The TensorRT python API segfaults on these graphs; see docs/06 in the GitHub repo for the pathology notes.

## What is not here, on purpose

- Checkpoints and any dataset-derived weights: upstream-hosted, link-only.
- Runner input bins: local runtime artifacts, regenerated by the pipeline (golden tier: anchor npz + checkpoint xy; smoke tier: random ctx + ckpt xy). No dataset pixels shipped except the single-scene golden anchor npz above.
